## S3 evidence and recovery
- Route: delegated direct (multi-file/preparation/execution). Implementation and self-verification complete; parent verification, work-unit commit/native assessment and activation pending. No S4 Java integration or migration.
- Ownership: one lifespan-owned, non-daemon Python worker with explicit stop/join and a single shared processing lock. No Redis/Celery/database/new dependency. Queued/running jobs resume from the private jobs subdirectory of the existing artifact volume. Dockerfile copies job_store.py; Compose volume/mount unchanged.
- Identity: caller supplies independent random 32-hex job ID and 64-hex capability; server stores only its SHA-256 hash and uses constant-time comparison. Submission verifies source SHA-256 and server engine/config fingerprint (package versions, actual selected ONNX model hashes, rendering limits/DPI and overlay version). Same ID/source/config is idempotent; mismatch is refused. No client filenames/paths are persisted.
- Admission: one bounded upload/preflight at a time, at most eight durable jobs and 32 combined artifact/job slots, with full input + 128 MiB output + 16 MiB checkpoint/result reservation per job, jointly enforced against legacy artifact bytes under the same lock and 512 MiB quota. Thus default quota admits approximately three full-size jobs, not an unlimited queue. Smaller configured artifact bounds are respected. Private manifests are bounded to 4 KiB each; atomic writes may additionally hold their bounded temporary manifest. Checkpoints are at most 256 KiB/page, 100 pages, and checkpoints plus result metadata together fit 16 MiB. Originals remain <=25 MiB, page/pixel bounds unchanged.
- Recovery: source and each page checkpoint are fsynced/atomically renamed; checkpoints publish immediately after recognition. RUNNING becomes QUEUED on restart, completed PDF pages skip rendering/inference; bitmap inputs rerender cached pages only to export, never repeat successful inference. Completed output/result publication survives restart without export/inference again. Corrupt sources/checkpoints or changed fingerprint fail closed with safe code; bounded startup scan refuses unknown/corrupt ownership. Interrupted private partials are reclaimed; original backend files/volumes are never deleted.
- Lifecycle: cancellation is cooperative at page/publication boundaries and cannot publish a cancelled result. Processing jobs and active download leases are protected from TTL cleanup; terminal jobs expire after one hour on admission/status/result/startup cleanup. DELETE cancels queued/running/error jobs, completed jobs remain available through TTL; it does not delete user originals. Repeated caller ID after ERROR/CANCELLED returns terminal status; an intentional retry needs a fresh caller ID. Legacy overload returns 503 instead of an unbounded worker queue; request cancellation retains the engine admission lock until its thread ends.
- S4 API contract: GET /v2/jobs/config => engineFingerprint,maxInputBytes,maxPages. POST /v2/jobs/{id} raw original body, headers X-Job-Capability, X-Source-SHA256, X-OCR-Fingerprint => 202 status. GET /v2/jobs/{id} with X-Job-Capability => id,state,phase,pages,completedPages,errorCode. States QUEUED/RUNNING/COMPLETED/ERROR/CANCELLED; phases QUEUED/RECOGNIZING/EXPORTING/COMPLETED/ERROR/CANCELLED. GET /v2/jobs/{id}/result with same header => existing text/confidence/pages/lines/model/layout plus artifact{id,capability,sizeBytes,sha256}, no Base64. GET /v2/artifacts/{id} with X-Artifact-Capability downloads either legacy or job-owned output; retry uses stored output, not inference. DELETE /v2/jobs/{id} with X-Job-Capability => cancellation status. After successful Java publication ONLY, DELETE /v2/jobs/{id}/result with X-Job-Capability =>204 durable acknowledgement/cleanup; wrong capability or already-cleaned/missing job=>404 (safe idempotent retry interpretation); unfinished=>409, active download/processing=>503 with result retained. Failed durable acknowledgement=>503 with completed result retained through TTL. Once acknowledged, private deletion is best-effort/restart-safe and retains a bounded quota-consuming tombstone until successful cleanup; repeat acknowledgement of a retained tombstone=>204. No public admin cleanup. All job responses private,no-store. Unavailable/wrong capability =>404; conflict/not-ready=>409; input/checkpoint/output bound=>413; admission/storage failure=>503; invalid source=>422. Health adds jobsReady independently of liveness status.
